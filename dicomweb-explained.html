DICOMweb, explained at the API level

The RESTful way to store, find, fetch and process medical images over HTTP(S). Defined in DICOM PS3.18. This page covers every service, the URL grammar, payloads, status codes, and lets you run a simulated PACS in your browser.

What is DICOMweb?

Classic DICOM uses its own binary network protocol (DIMSE over port 104/11112) with associations, AE titles and C-commands. DICOMweb maps the same ideas onto plain HTTP so browsers, mobile apps and cloud services can use them without a DICOM toolkit.

Classic DICOMDICOMwebPurpose
C-STORESTOW-RS (POST)Upload instances
C-FINDQIDO-RS (GET)Search studies, series, instances
C-MOVE / C-GETWADO-RS (GET)Retrieve instances, metadata, frames, rendered images
Modality Worklist, MPPSUPS-RSWorklist and procedure step management
(none)Delete, CapabilitiesRemove objects, discover server features

Architecture

Any HTTP client talks to a DICOMweb server (often a gateway in front of a PACS/VNA). The gateway translates to the archive's storage and database.

The services

QIDO-RS
Query based on ID for DICOM Objects. Returns matching attributes as DICOM JSON.
WADO-RS
Web Access to DICOM Objects. Returns full instances, metadata, bulk data, frames, rendered images, thumbnails.
STOW-RS
Store Over the Web. Multipart upload of instances, returns a per-instance result.
UPS-RS
Unified Procedure Step. Create, claim, update and subscribe to worklist items.
WADO-URI
Legacy single-URL retrieval using ?requestType=WADO query parameters.
Delete / Capabilities
DELETE on study, series, instance. OPTIONS returns a WADL description of support.

URL grammar and resource hierarchy

Everything hangs off a base URL. DICOM identity is the hierarchy Patient (not a URL level) to Study to Series to Instance to Frame.

QIDO-RS: search

GET with matching parameters. Responses are application/dicom+json arrays, one object per match. Status 200 with results, 204 when nothing matches.

GET /seriesSeries across all studies
GET /instancesInstances across all studies
GET /studies/{uid}/seriesSeries in one study
GET /studies/{uid}/series/{uid}/instancesInstances in one series

Transfer syntax negotiation: if the stored syntax differs from the requested one the server may transcode. Use transfer-syntax=* to accept anything stored.

STOW-RS: store

POST a multipart/related body. Each part is one DICOM Part 10 file. Post to /studies (any study) or /studies/{uid} (must match).

POST /studies HTTP/1.1
Content-Type: multipart/related; type="application/dicom"; boundary=XYZ
Accept: application/dicom+json

--XYZ
Content-Type: application/dicom

<binary Part 10 bytes>
--XYZ--

Response body is a DICOM JSON dataset with ReferencedSOPSequence (00081199) for stored instances and FailedSOPSequence (00081198) with a FailureReason (00081197) for rejects.

HTTP/1.1 200 OK   (all stored)   |  202 Accepted (some warnings)  |  409 Conflict (all failed)

DICOM JSON model

Each attribute is keyed by its 8-hex-digit tag. Value is an object with vr and either Value (array), BulkDataURI or InlineBinary. Person names use Alphabetic.

{
 "0020000D": {"vr":"UI","Value":["1.2.840.113619.2.55.3"]},
 "00100010": {"vr":"PN","Value":[{"Alphabetic":"Doe^Jane"}]},
 "00080061": {"vr":"CS","Value":["CT"]},
 "00201208": {"vr":"IS","Value":[412]},
 "7FE00010": {"vr":"OW",
   "BulkDataURI":".../bulkdata/7FE00010"}

Typical viewer workflow


How a web viewer opens a study. Press play to step through it.




    

  1. QIDO GET /studies?PatientID=P1001 lists the patient's studies.
    2. 

  2. QIDO GET /studies/{s}/series shows the series and modality.
    3. 

  3. WADO GET /studies/{s}/metadata loads tags and geometry for layout and MPR.
    4. 

  4. WADO GET .../frames/1 fetches compressed pixels, usually in parallel and prefetched.
    5. 

  5. Client decodes (JPEG-LS, J2K, HTJ2K) and applies window/level on the GPU.
    6. 

  6. STOW POST /studies saves a key image, SR or segmentation back to the archive.

Practical advice


  • Always send Authorization: Bearer over HTTPS; avoid PHI in URLs where logs retain them.
    • 

  • Request metadata once, cache it, and fetch frames lazily.
    • 

  • Negotiate transfer syntax to avoid server transcoding at scale.
    • 

  • Page QIDO with limit and offset; check the Warning header for truncation.
